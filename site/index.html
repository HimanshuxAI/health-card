A digital health card that a responder can read before the ambulance arrives.

The patient carries an emergency trauma profile on a signed QR code. A hospital scans it and gets blood group, allergies, conditions, medications and emergency contacts in about one millisecond, without an account and without the patient's data leaving the record store. Visits become HL7 FHIR v4 records, bills become NHCX claims, and the panic button reaches every emergency contact by email and every hospital dashboard over a live WebSocket.

Five FastAPI services, one NGINX gateway, one Next.js frontend. Each service owns its own SQLite database. ABDM and NHCX gateways are simulated in-process, so the system runs with no external dependency.

1 ms Emergency profile decryption
5 Independent services, each with its own database
3 Roles: patient, hospital, administrator

Run it

Build from source and start the whole stack on one command.

git clone https://github.com/HimanshuxAI/health-card.git
cd health-card
docker compose up --build

The gateway and the frontend are on http://localhost, the frontend is also on http://localhost:3000, and the five services are on ports 8001 to 8005. Seed data is created on first boot.

To run without the source tree, pull the published images instead.

docker compose -f docker-compose.ghcr.yml up -d

Deployment

GitHub Actions builds and tests every push, then publishes the images to GitHub Container Registry.

docker pull ghcr.io/himanshuxai/health-card-frontend:latest
docker pull ghcr.io/himanshuxai/health-card-services:latest
  • Workflow runs cover the backend tests, the live smoke test, the frontend type check and build, and the image builds.
  • Container packages are published on every push to main and on v* tags.
  • docker-compose.ghcr.yml runs the published images with the databases on a named volume, so a deployment needs no source tree and keeps its data across restarts.
  • This page is served by GitHub Pages from the same repository.

What this build does not do

  • The scanner reads a pasted token. There is no camera decode in the web build.
  • Emergency contacts are notified by email. There is no SMS gateway. Without SMTP credentials the alert still fires and the status reads SKIPPED.
  • ABDM and NHCX are simulated inside our own services. The endpoints follow the real shapes, but no government sandbox is called.
  • Each service owns one SQLite file. There are no cross-service transactions and no shared event bus beyond the WebSocket broadcast.
